Java Interview Preparation Guide

Most Asked Questions, Answers & Practice Problems (FAANG-Style)


1. Core OOP Concepts

Q1. What are the four pillars of OOP? Explain each briefly.


Encapsulation: Bundling data and methods together, restricting direct access via private fields and public getters/setters.
Abstraction: Hiding implementation details and exposing only essential features (via abstract classes/interfaces).
Inheritance: A class acquiring properties and behavior of another class using extends.
Polymorphism: One interface, multiple implementations — achieved via method overloading (compile-time) and overriding (runtime).


Q2. Why does Java not support multiple inheritance with classes?
To avoid the "Diamond Problem" — ambiguity when two parent classes have a method with the same signature and the compiler cannot decide which one to inherit. Java solves this using interfaces, where default method conflicts must be explicitly resolved by the implementing class.

Q3. Difference between method overloading and overriding?

Overloading   Same method name, different parameters  Resolved at compile time Can occur in the same class  Return type can differ   

Overriding   Same method name and signature   Resolved at runtime   Requires inheritance   

Q4. Abstract class vs Interface — when to use which?


Abstract classes can have constructors, instance variables, and a mix of abstract/concrete methods — use when classes share a common base and state.
Interfaces (Java 8+) can have default and static methods but no instance state — use when unrelated classes need to guarantee a contract/behavior.
A class can implement multiple interfaces but extend only one abstract class.


Q5. What is the difference between this and super?
this refers to the current object instance (used to resolve variable shadowing or call another constructor in the same class via this()). super refers to the immediate parent class — used to call parent constructors (super()) or access parent methods/fields hidden by overriding.


2. Strings & Memory

Q6. Why is String immutable in Java?
For security, thread-safety, caching (String Pool), and hashcode consistency (so it's safe as a HashMap key). Once created, internal char/byte array references can't be changed; operations like concatenation create new objects.

Q7. String vs StringBuilder vs StringBuffer?


String: immutable.
StringBuilder: mutable, not thread-safe, faster — use in single-threaded contexts.
StringBuffer: mutable, thread-safe (synchronized methods), slightly slower.


Q8. What is the String Pool?
A special memory area in the heap where string literals are stored to avoid duplicate objects. String s1 = "hi" checks the pool first; new String("hi") always creates a new object on the heap, bypassing the pool unless .intern() is called.

Q9. Difference between == and .equals()?
== compares references (memory addresses) for objects, or values for primitives. .equals() compares logical/content equality and can be overridden (e.g., String, Integer override it; default Object implementation just does ==).

Q10. What is the hashCode-equals contract?
If two objects are equal via .equals(), they must have the same hashCode(). Violating this breaks HashMap/HashSet behavior — equal objects could land in different buckets and lookups would fail.


3. Collections Framework

Q11. ArrayList vs LinkedList?


ArrayList: backed by a dynamic array, O(1) random access, O(n) insert/delete in the middle.
LinkedList: doubly linked list, O(1) insert/delete at ends, O(n) random access. Use ArrayList for frequent reads, LinkedList for frequent insertions/deletions.


Q12. How does HashMap work internally?
Keys are hashed via hashCode(), then mapped to a bucket index using hash & (n-1). Each bucket holds a linked list (or a red-black tree if a bucket exceeds 8 entries, since Java 8) of entries to handle collisions. On get(), the key's hash locates the bucket, then .equals() finds the exact match.

Q13. HashMap vs TreeMap vs LinkedHashMap?


HashMap: no ordering guarantee, O(1) average access.
LinkedHashMap: maintains insertion order, slight overhead.
TreeMap: sorted by natural order/comparator, O(log n) operations (backed by a Red-Black tree).


Q14. HashMap vs ConcurrentHashMap?
HashMap is not thread-safe. ConcurrentHashMap divides data into segments/buckets with finer-grained locking (CAS operations and synchronized blocks per bucket in Java 8+), allowing concurrent reads and writes without locking the whole map, unlike the older Hashtable which synchronizes every method.

Q15. Fail-fast vs Fail-safe iterators?
Fail-fast iterators (ArrayList, HashMap) throw ConcurrentModificationException if the collection is structurally modified during iteration. Fail-safe iterators (CopyOnWriteArrayList, ConcurrentHashMap) operate on a clone or snapshot, so concurrent modification doesn't throw an exception.



4. Exception Handling

Q16. Checked vs Unchecked exceptions?


Checked (e.g., IOException, SQLException): must be declared with throws or handled with try-catch; checked at compile-time.
Unchecked (e.g., NullPointerException, ArithmeticException): subclasses of RuntimeException; not enforced at compile-time.


Q17. finally vs finalize()?
finally is a block that always executes after try-catch, used for cleanup (closing resources). finalize() is a method called by the garbage collector before object destruction — deprecated since Java 9 and unreliable for resource cleanup; use try-with-resources instead.

Q18. Can you have a try block without a catch block?
Yes — try with finally only, or try-with-resources without a catch, is valid.

Q19. What happens if an exception is thrown inside a finally block?
It suppresses any exception from the try/catch block and propagates instead, which can hide the original error — a common reason to avoid throwing exceptions inside finally.
